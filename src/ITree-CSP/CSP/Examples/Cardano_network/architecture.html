A network of n nodes over NetworkLink

The same composition as the four-node example, written generically: n nodes, m links, arbitrary topology. The medium is the concrete per-link multiplexer NetworkLink (breakable), replacing the abstract CopySpec. The wiring pattern is independent of node and link count.

-- top level: one medium, n interleaved nodes, io hidden
system  = ( Medium ∥⇘ ioES ⇙ ( ⦀ i∈Nodes · nodeᵢ ) ) ∖ ioES

-- medium = concrete mux, one independently-breakable cell per link
Medium  = ⦀Fin m ( λ l → NetOneLink l △ (break l ⟶₀ Skip) )
        -- drop the △-interrupt for the non-faulty system

01 Top-level composition  ·  parametric in n, m

One hiding frame over a single generalised-parallel rendezvous: the link medium on the left, the n interleaved nodes on the right, synchronised on ioES = {|input, output|} and then hidden. Both operands scale with the topology — m link cells, n node processes.

Roles are per node, not per topology. Each nodeᵢ is a source (produce), sink (consume), or relay (consume then produce) depending only on which links it is incident to and which direction it drives them. Add nodes/links by extending n, m and the incidence — the composition shape is unchanged. break l is deliberately outside ioES, so link faults stay observable while all wire traffic is hidden.

02 One link, two endpoints — the mini-protocol level

Zoom into a single edge of the graph. Each of the two nodes it joins runs the full set of mini-protocol peers; a node's outgoing traffic is multiplexed by its TxSide (send mux) and the peer's incoming traffic is demultiplexed by its RxSide (recv demux). The two sides are joined by a full-duplex link — data frames (tx) one way, acknowledgements (ack) back — in each direction independently. This is NetOneLink l seen with both of its endpoints attached.

nodeᵢ ⟷ nodeⱼ  over link lfull-duplex, per mini-protocol
cl ↔ sv: for each protocol, nodeᵢ's client talks to nodeⱼ's server, and nodeⱼ's client to nodeᵢ's server — the two duplex directions.
input / output (peers ↔ mux) tx · data frames ack mini-protocol peer (client + server) Tx / Rx mux
Both endpoints of every edge look like this. On each link a node runs both the client and the server of every configured mini-protocol (only two shown; the rest follow the same pattern). All those peers are muxed onto one wire per direction — tx forward, ack back. What §03 opens up is the inside of one TxSide/RxSide pair — the same boxes, shown with their hidden sndmsg/tx/ack/… channels. In the abstract CopySpec model this entire duplex collapses to one input?x → output!x buffer per lane.

03 Inside one NetOneLink l — the multiplexer

The concrete medium the swap introduces. Each link is a two-sided mux: a TxSide that bundles per-mini-protocol inputs onto one wire, and an RxSide that unpacks them, connected by a transmit/acknowledge handshake. Solid arrows are visible input/output; every internal channel is hidden. Identical for every link, at any link count.

Which lanes are live is per link. Inputs/Outputs carry one lane per configured mini-protocol for link l (from linkConfig l) — the six above are the full N2N + Leios set; a given link may run any subset. The abstract CopySpec collapses this whole box to a single input?x → output!x buffer per lane — same observable behaviour, none of the handshake.

05 Arbitrary topology

Nodes and links form any graph. Every edge is one NetOneLink instance (the mux above); every node runs mini-protocol peers on each of its incident links. The four-node diamond is just one instantiation (n = 4, m = 4).

edge = NetOneLink. A link carries several protocol conversations (KeepAlive / ChainSync / BlockFetch / TxSubmission, + Leios) multiplexed over one wire — the lanes in §02–§03. node = peers ∥ app-logic. A node opens client/server peers on each incident link and drives them from its application logic. Breaking any link severs that edge; the rest of the graph runs on — which is what the liveness proofs check: can data still reach its destination by another path?

Why the swap holds for any n, m. NetworkLink ≈FD CopySpec is proved per link and lifts through the interleaving (⦀Fin m), so the concrete mux is a failures-divergences drop-in for the abstract buffer at any link count. Nodes only ever touch input/output (plus api*/break); every mux channel (tx, ack, sndmsg, rcvack, rcvmsg, sndack) is hidden inside NetOneLink, so it never surfaces to the composition — the wiring in §01 is truly independent of topology size.
